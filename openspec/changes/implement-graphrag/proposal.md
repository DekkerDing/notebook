# Proposal: 实现GraphRAG模块

## Why

当前RAG系统仅基于向量相似度进行检索，无法处理多跳推理和复杂关系查询。例如"用户A参与的所有项目"这类跨文档关联查询无法有效回答。GraphRAG通过知识图谱增强检索，可以：
1. 捕获实体间的复杂关系
2. 支持多跳推理查询
3. 提供更精准的上下文检索
4. 改善多文档问题的回答质量

## What Changes

- **新增知识图谱模块**：实现实体抽取、关系抽取、图存储
- **新增图数据库集成**：支持图数据的存储和查询（使用Neo4j或内存图）
- **新增图检索策略**：实现基于图谱的检索增强
- **新增图查询API**：提供图谱关系查询接口
- **集成到RAG流程**：GraphRAG + 向量RAG混合检索

## Capabilities

### New Capabilities

- **graph-entity-extraction**: 实体抽取能力
  - 从文本中识别和抽取实体
  - 支持自定义实体类型（人物、组织、地点等）
  - 支持实体消歧和链接

- **graph-relation-extraction**: 关系抽取能力
  - 从文本中识别实体间关系
  - 支持自定义关系类型
  - 支持关系属性抽取

- **graph-storage**: 图存储能力
  - 支持图数据库存储（Neo4j）
  - 支持内存图存储（作为备选）
  - 提供图CRUD操作

- **graph-query**: 图查询能力
  - 支持多跳关系查询
  - 支持图模式匹配
  - 支持图算法（最短路径、社区发现等）

- **graphrag-retrieval**: GraphRAG检索能力
  - 基于图谱的上下文检索
  - 图谱+向量混合检索
  - 社区摘要生成

### Modified Capabilities

无现有能力变更（全新模块）

## Impact

**影响范围**：
- 新增`graph`模块
- 新增图数据库依赖（Neo4j或内存图）
- 新增实体/关系抽取服务
- 扩展检索策略，增加图检索选项

**新增依赖**：
- Neo4j Java Driver 4.x（图数据库）
- 或使用内存图库（JGraphT）
- NLP工具（实体识别：spaCy或类似）

**兼容性**：
- 向后兼容，不影响现有向量检索
- 新增功能，用户可选择使用

**性能目标**：
- 实体抽取：<500ms/KB文本
- 关系抽取：<800ms/KB文本
- 图查询：<200ms/查询
- 混合检索：<300ms/查询

## 非功能需求

### 准确性目标
- 实体识别F1：>85%
- 关系抽取Precision：>80%
- 图检索召回率：>75%

### 可扩展性
- 支持百万级实体和关系
- 支持多知识库图隔离
- 支持图的增量更新
